An agentic SDLC framework for Python

Your lifecycle is executable code.

Not a manifest, not a spec, and not something that generates a pipeline — the module you write is the thing that runs. Code review, implement, bug fix, triage, backport and RFE, executed by AI models under budgets, approval gates and a tamper-evident ledger.

.lockstep/lockstep.py — the whole configuration
from in_lockstep import Lockstep
from in_lockstep.adapters import (
    PytestTest, RuffValidate, Test, Validate,
)
from in_lockstep.middleware import (
    CostBudget, otel,
)

lockstep = Lockstep.detect()
lockstep.bind(Test, PytestTest(args=["-q"]))
lockstep.bind(Validate, RuffValidate())
lockstep.middleware += [
    otel(), CostBudget(usd=2.00),
]

A change to your review policy becomes a diff in a pull request — with blame, history and rollback. Extend a verb by subclassing, override by rebinding, compose cross-cutting concerns as middleware. in-lockstep ls prints what will actually run.

The panel

Eleven readers, one repository.

Before this page was written, eleven independent reviewers — each playing a different role in an enterprise software organization — read the repository and reported the features that mattered most to them, with the evidence that backs each claim.

Their reservations are published alongside their endorsements, because that is this project's own discipline: a claim without a test is just a claim. (docs/needs.md lists "an entry surface that routes by persona" as an open need. You are looking at it.)

01

Engineering Manager

Delivery predictability, spend visibility, adoption friction.

Spend controls, before the invoice

I can put a real dollar cap on what a run — and a day — costs, instead of finding out from an invoice line after a chat-ops loop fires all night.

evidence · CostBudget(usd=2.00) · IN_LOCKSTEP_DAILY_LIMIT · org-limit attestation checked by doctor (DOC101)

two more findings
  • Cassette replay for onboarding and CI. The team demos and CI-gates the review workflow with zero API spend and zero flakiness from live model calls.
  • A ledger for 2 a.m. accountability. "Who approved this AI change and what did it cost" is answered by an append-only record, not a Slack thread.

Filed reservation doctor fails a fresh repo with two errors on purpose — the setup pass is real work, and it gets skipped under deadline pressure unless doctor is a hard onboarding gate.

02

Director of Engineering

Standardization across ~50 engineers, governance that scales, lock-in.

Org standards as an installable package

One place to set the floor — deny_tools, input scanning, turn limits — and a repo can tighten it but never quietly weaken it. I am not chasing two hundred copy-pasted config files.

evidence · in_lockstep.standards entry points at Tier.PLUGIN · tighten-only merge · worked example in examples/acme-standards · in-lockstep ls as the audit surface

two more findings
  • An honest verification story. The ledger's tamper-evidence states exactly where the guarantee ends — a force-push is stopped by branch protection at the remote, not by any local walk — instead of papering over it.
  • Not a lock-in play. Providers are install-time extras ([anthropic], [openai], [google], [bedrock]), and cassettes recorded against one provider replay against another.

Filed reservation As a library, the governance floor depends on every team wiring the trampoline, branch protection and egress enforcement correctly — a real rollout and audit burden the project itself is candid about.

03

Senior Tech Lead

Architecture quality, extension seams, allergic to magic.

Tamper-evidence, not tamper-logging

Most audit logs are a table anyone with prod access can quietly edit. This one detects its own rewriting — the difference between an audit trail and a compliance placebo.

evidence · GitLedger.verify() walks the lockstep-history orphan branch · records modified or deleted after append are flagged · doctor fails on a rewritten ledger (DOC167)

two more findings
  • Capability-driven policy, one seam. Bindings declare EXECUTES_CODE, REACHES_NETWORK, SPENDS_BUDGET — so egress enforcement, approval gates and retry-safety key off declared capabilities instead of adapter-name string matching scattered through middleware.
  • A trampoline contract that can't rot. The credential split is six enumerated, testable clauses in docs/trampoline.md, with a CI test enforcing the workflow YAML's shell-line budget — not tribal knowledge in a wiki.

Filed reservation Every mitigation runs in the same process as the model call. That is a fundamentally different trust boundary than an execution substrate, and the docs say so plainly.

04

Team Lead

Day-one friction, the daily loop, whether juniors can use it safely.

The lifecycle you can actually read

A pull request that touches lockstep.py is reviewable like any other code change, not a black box — ls prints the resolved bindings, middleware, standards and policy that will actually run.

evidence · in-lockstep ls · sample output in docs/getting-started.md · "a container is harder to read than a manifest, which is what ls is for"

two more findings
  • Safe for juniors on day one. review --offline replays real, recorded model findings for zero dollars and zero risk — before anyone is trusted with a live key or a budget.
  • It refuses rather than trusts. An adapter that lets a model write or execute with no approval path in the middleware chain is refused at startup (GATE-APPROVAL-1).

Filed reservation The honesty is itself the signal: GitLab is "partial", the shared ledger store is "planned", and a fresh install fails doctor until someone who has read the controls crosswalk does the setup pass.

05

Software Engineer

The local loop, debugging, working without a key.

Offline, keyless, deterministic — on a fresh clone

No key, no network, no recording of my own — review --offline still shows real model findings from a shipped cassette. That is how I poke at a tool before I trust it with my org's key.

evidence · cassette recorded against a real merged PR ships in the wheel · replays print cost $0.0000 (replayed; nothing was billed)

two more findings
  • show-prompt, offline. When a review comes back weird, "what was the model actually told?" must not cost a run — the composed prompt prints with no key at all.
  • Config is Python I can grep. bind() and route() calls I can diff and subclass — not another YAML DSL to fight.

Filed reservation A misbehaving strategy runs with whatever access my process already has — the isolation (egress policy, sandboxed worktrees, doctor checks) is mine to wire, not free.

06

Quality Engineer

Determinism, reproducibility, how AI output is verified.

Cassettes at the LLM seam, not the HTTP layer

A test suite that hits a live model is a slot machine. Replays are deterministic — and a replay that would silently call out raises an error instead, because "a replay that silently called out would not be a replay."

evidence · cassettes keyed on the provider-agnostic LLMInput/LLMOutput seam · they capture tool IO as well as model IO · ReplayProvider refuses a cassette miss

two more findings
  • A gate ledger with a taxonomy for lying to yourself. design/gates.md distinguishes held / unit only / unmet — and admits which of its own controls were caught existing with no caller on any live path.
  • Eval subjects that can't drift silently. Subjects are keyed on content hashes of the composed prompt and skillset, and the coverage gate fails when the floor quietly rises unrecorded, not just when it drops.

Filed reservation The flaky-test adapter is still planned (roadmap item 26) — today an unattended fix run has no first-class signal to tell a flaky test from a broken one.

07

Documentation Lead

Docs accuracy, drift, information architecture.

Docs drift is a failing test

My biggest fear is a table that says "runs" for a feature that quietly broke. Here, a runs row must name a verb that ships, a planned row must not have quietly shipped — and CI enforces both directions.

evidence · tests/in_lockstep/test_docs.py execs the README's code block and the cookbook's recipes · quickstart output lines are asserted against the real CLI

two more findings
  • Copy-paste can't break. The test suite's own docstring records the postmortem — three separate readers hit the same NameError from an unexecuted README snippet, so now the snippets execute in CI.
  • Gaps owned in writing. The controls crosswalk tells the reader to cross-check design/gates.md before citing any of its rows as evidence — self-correction left visible in the text.

Filed reservation There was no persona-routed entry surface — docs/needs.md N13, open. This page is the answer to that reservation.

08

Product Manager

Ticket-to-PR flow, triage automation, honest scoping.

/implement — ticket in, pull request out

A developer types /implement on an issue and the framework reads the ticket, stages a change and opens a PR — the idea-becomes-shipped-code loop I am trying to shorten, without anyone hand-holding it through CI.

evidence · three-job trampoline (gate / work / propose) · issue_comment and ai-generated-label triggers · docs/trampoline.md

two more findings
  • My backlog lives in Jira, and that's fine. A native JiraSource reads the ticket, parses acceptance criteria out of the description, and transitions and comments back.
  • Ideas become tickets a human approves. rfe --idea "…" drafts problem, proposal and acceptance criteria — and never files itself; --create is a separate, human step.

Filed reservation Before promising this to a cross-functional team I need our exact tracker and CI host in the "runs" column — GitLab is partial, and there's no Linear or Azure DevOps source.

09

Business Leader

Cost control, ROI, audit trail, runaway-spend risk.

Cost avoidance, not just cost caps

Routine triage routes to a local model and bills exactly zero — while tokens are still counted, because free is not unmeasured. Premium spend goes where premium judgment is needed.

evidence · route(Verb.TRIAGE) to a local model — the $0 path · per-run CostBudget · rolling 24-hour IN_LOCKSTEP_DAILY_LIMIT refused pre-run

two more findings
  • An answer for the auditor. Every run lands in an append-only record; report flags anything rewritten after append rather than staying silent.
  • Demos are free forever. Record a workflow once, replay it deterministically at $0 for every evaluation, demo and regression check after.

Filed reservation The daily ceiling sums this clone's own ledger — until the shared store ships, the provider-console org limit is the real backstop, and the tool itself tells you to set it.

10

Enterprise Customer

Platform engineer at a regulated company; build-vs-buy.

A privilege boundary, not a promise

The process holding the model API key never also holds repo write access — on GitHub, by not even installing the provider extra in the write job. That is a control I can put in a SOC2 narrative.

evidence · trampoline clause 3: credentials never co-resident · in-lockstep egress-manifest prints the hosts a run may dial · IN_LOCKSTEP_EGRESS=enforced probes a known-blocked host and refuses the run if it connects

two more findings
  • Keyless CI. GitHub OIDC exchanged at Anthropic — no ANTHROPIC_API_KEY sitting in repository secrets at all.
  • Tamper-evidence with a documented blast radius. The docs answer "how do I know the run log wasn't rewritten," including the part local verification cannot fix — before an incident forces the question.

Filed reservation Keyless CI is Anthropic-specific today — a Bedrock or OpenAI lane in the same pipeline is back to a static key. And the in-process posture is one I accept, not one I can bolt on later.

11

Vice President of Engineering

Executive sponsor; defensibility to the board and auditors.

A system that doesn't grade its own homework

The capability table is held by CI, the ledger detects rewritten history, and the crosswalk publishes exactly which controls got weaker in the move to a library. That is the kind of self-policing that survives due diligence.

evidence · two-sided what-ships test · GitLedger.verify() · controls-crosswalk rows marked "replaced, weaker by construction" with named compensations

two more findings
  • Policy with blame and rollback. Review policy is a Python diff in a pull request — a lifecycle I can hold engineers accountable for in review, not a rendered artifact.
  • They kill dead architectures. ADR 0001 records the team archiving the 0.1.x compiler line rather than letting it linger — they'll do it again if this bet stops paying.

Filed reservation It's a 1.0 that replaced a 0.1.x with zero adopters. Before an org-wide rollout, show me report --by model from real runs against our repositories — the project's own standard of evidence, applied to itself.
