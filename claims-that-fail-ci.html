Three ratchets, each failing in both directions

The capability table

The table on the front page is read by a test. A row claiming runs must name a verb or command that exists; a planned row must not. Shipping a feature without flipping its row fails CI — and so does deleting a feature the table still advertises. The safe-looking drift and the dangerous one both break the build.

The gate ledger, and a status most projects do not have

design/gates.md tracks every claimed control against the test that holds it, and it invented a status called unit only: the mechanism exists, it is unit-tested, and nothing calls it during a run — which is not a pass. Nine rows were in that state while another document was citing them as evidence that a control had been replaced.

The ledger is itself a ratchet: a gate marked held must be discharged by a test that names it, and a gate marked unmet must be discharged nowhere — so implementing one without updating its row fails, in both directions.

The scan that guards the scan

Anything leaving the process must go through the redacting sink. The check is an AST scan for the raw primitives, with three meta-assertions around it: one fails if the matcher stops matching anything, one deletes exemptions whose call sites are gone, and one rejects an exemption whose stated reason is under sixty characters.

What it does not do

The discipline is one person's attention, and it lapses

The reviews that produced this page found two lapses in an afternoon, and both were real.

A security test that only ran one way. Three tests asserting a sandboxed child cannot read the parent's credentials hard-coded the interpreter as python. Under make check they passed, because the runner puts a python shim on the path; run any other way they failed. A gate that passes only under one invocation of the test runner is worse than a red one, because nothing says so.

Tightening the path guard weakened it. The tier-1 rules protecting conftest.py, *.pem and .env* were gated on an identity check against the shipped tuple — so an organisation adding one of its own protected prefixes silently switched four protections off. Adding a rule removed four.

Both were fixed the day they were found, with tests that would have caught them. The honest reading is not that the discipline is theatre — it is that a ratchet only holds where somebody thought to put one, and a single maintainer has a finite number of afternoons.
