Spend is refused, not reported

A budget you read on Monday is a report. A budget that stops a run before it starts is a control. The difference matters most for exactly the runs nobody is watching, which is the only kind worth automating.

Four layers, and the numbers are measured

  • A predictive per-run budget. The check runs before each turn against the projected cost of making it, so a run is blocked before the call that would cross the ceiling rather than after it.
  • Budgets merge to the lowest, not the last. Two contributions each setting a ceiling are two constraints; satisfying only whichever was read last satisfies neither.
  • A rolling 24-hour ceiling read off the ledger, checked before a run starts and scoped to lifecycles that can actually spend.
  • An unpriced model is blocked with zero model calls. Not estimated, not defaulted — a rate the framework does not know is a refusal, because the alternative is a fabricated number in a budget check.

The scaffolded ceiling was raised from $0.25 to $0.75 after a real run showed a full-context review projects $0.2414 and costs $0.189. That is the sort of number this project will not invent: the estimator is required to be cumulative-token-based specifically so that quadratic context growth stays visible rather than hidden behind a flat per-turn fee.

What it does not do

Every ceiling here lives in the same process as the API key

The framework says this about itself before anyone else can. Model invocation happens in your process — that is what makes it a library rather than a service — and it removes an execution substrate that was also an out-of-process spend ceiling. An in-process budget is weaker by construction: a bug in the process holding the key is a bug in the thing supposed to be bounding it.

So the only cap a bug cannot defeat is the one at your provider, and doctor will not pass until you attest that you have set one (DOC101, an error on a fresh install). The per-day ceiling the old substrate enforced is booked in the controls crosswalk as lost rather than replaced — the entry says so in that word.
